# Relatório — GEMINI.md sincronizado e porte dos agentes para `.gemini/` (2026-09-16)

Branches: `develop_natan` (base `main`)

## Contexto

Via skill de grilling (`/grill-with-docs`), o usuário pediu um `GEMINI.md` "sincronizado com o `CLAUDE.md`",
usando como modelo o `GEMINI.md` do repo irmão `artigos_tech_pulse` (caminho local
`../artigos_tech_pulse/GEMINI.md`, fora da árvore deste repositório — por isso não há link relativo aqui). A
leitura do modelo mostrou que ele **não copia** o contrato: declara-se substituído e aponta para o
`CLAUDE.md`, porque uma versão anterior espelhava as regras editoriais e divergiu do que os artigos de fato
fazem.

A exploração do repo irmão revelou ainda a razão de ele **duplicar** o corpo das skills em vez de usar
ponteiro, registrada no `docs/ARCHITECTURE.md` de lá: *"não há evidência de que o `agy` siga ponteiros para
outro arquivo — uma skill reduzida a um ponteiro pode chegar ao agente sem instruir nada."* Essa evidência
separou o desenho em dois: **contrato** aponta (é um arquivo de contexto que o agente lê e age sobre),
**skill** duplica (precisa se auto-instruir).

Levantamento completo das decisões e dos fatos em
[../../../survey/20260916_gemini_md_surveyfacts.md](../../../survey/20260916_gemini_md_surveyfacts.md).

## Implementado

### 1. `GEMINI.md` — import em vez de cópia

[../../../../GEMINI.md](../../../../GEMINI.md) tem três blocos e **nenhuma regra própria**: cabeçalho,
duas linhas de import (`@./CLAUDE.md`, `@./CONTEXT.md`) e prosa de rede.

O Gemini CLI resolve `@./arquivo.md` **inline no contexto**, recursivo, profundidade máx. 5, ciclo detectado,
restrito à raiz do projeto — ou seja, o arquivo é *literalmente* sincronizado sem ser uma cópia, e não tem
como divergir. A prosa existe porque o import é um recurso do **Gemini CLI** e o runtime-alvo aqui é o
**Antigravity**: se o `agy` não resolver import, ela ainda instrui o agente a abrir os dois arquivos.

### 2. Skills do Antigravity

| Item | O quê | Onde |
|---|---|---|
| 1 | Skill de layout, corpo idêntico ao agente Copilot | [../../../../.gemini/skill/tech_pulse_layout/SKILL.md](../../../../.gemini/skill/tech_pulse_layout/SKILL.md) |
| 2 | Skill de admin, corpo idêntico ao agente Copilot | [../../../../.gemini/skill/tech_pulse_admin/SKILL.md](../../../../.gemini/skill/tech_pulse_admin/SKILL.md) |

Diretório em `.gemini/skill/` (**singular** — o Claude usa `skills/` plural), frontmatter com `---` na
**linha 1** (um título antes dele faz a skill perder `name` e `description`) e só as chaves `name` +
`description`. Cada arquivo tem `name`, bloco de invocação (`agy run <id> "<change description>"`) e o
corpo copiado de `## Scope` para baixo.

### 3. Sincronia entre os dois runtimes

Como os dois lados coexistem, cada par carrega um bloco `## Sincronia` — **o mesmo texto nos dois arquivos
do par**, deliberadamente dentro do trecho comparado: como o comando `diff` cita os dois caminhos, a string
fecha dos dois lados. O marcador é `## Scope` (primeiro `##` de ambos, robusto e greppável) e o bloco publica
o comando de conferência.

## Defeitos factuais encontrados e corrigidos

Todos verificados contra `package.json`, `composer.lock`, `tailwind.config.js`, `routes/web.php` e o
ADR-0001. Corrigidos **nos dois lados** (`.github/agents/` e `.gemini/skill/`) para que o `diff` continue
significando "os runtimes estão alinhados".

| # | Onde | Dizia | Realidade |
|---|---|---|---|
| 1 | layout:14-15, admin:14 | `doc/prototipos/versao_3/...` | a pasta é `docs/` — a "fonte de verdade" declarada apontava para diretório inexistente |
| 2 | layout:32, admin:29 | `app.css`, `home.css`, `article.css`, `sass/custom.scss` são "legacy Bootstrap — do not use" | **nenhum dos quatro existe**; Bootstrap foi removido (ADR-0001, Fase 5) |
| 3 | layout:31, admin:28 | `corePlugins.preflight` está **desligado** | `tailwind.config.js` **não tem** a chave → preflight no default, **ligado** |
| 4 | admin:15, admin:44 | `Components/MarkdownEditor.vue` | o caminho real é `Components/Admin/MarkdownEditor.vue` |
| 5 | admin:35 | `categories.update` PUT `/update/{uuid}` | o param é `{category}` (`routes/web.php:80`) |
| 6 | admin:51 | "componentes **novos**: `ImageDropzone.vue`, `TagInput.vue`" | já existem em `Components/Admin/` |

O defeito 3 é o mais instrutivo: o ADR-0001 planejou religar o preflight "na Fase 5 (remoção do Bootstrap)",
o `package.json` não tem `bootstrap`, o `node_modules/bootstrap` não existe, `resources/css/` só contém
`tailwind.css` e `resources/js/bootstrap.js` é apenas o scaffold axios do Laravel. A migração terminou; os
agentes continuavam descrevendo o mundo anterior a ela.

## Validação executada

- **Sincronia dos dois pares** — `diff <(sed -n '/^## Scope/,$p' <agente>) <(sed -n '/^## Scope/,$p' <skill>)`
  → vazio nos dois. **Sincronizados.**
- **Frontmatter na linha 1** — `head -1` de cada `SKILL.md` imprime `---`.
- **Caminhos mortos** — `grep` por `doc/prototipos`, `resources/sass`, `app.css`, `home.css`, `article.css`,
  `Components/MarkdownEditor` em `CLAUDE.md`, `.github/agents/` e `.gemini/` → nenhum resultado.
- **Afirmação do preflight** — nenhuma ocorrência de "disabled" restante.
- **`Bootstrap 5` no `CLAUDE.md`** — 0 ocorrências.
- **Existência dos caminhos citados** — todos os 8 caminhos conferidos existem.
- **Fim de linha** — arquivos novos em LF, sem CRLF.

### Pendência de verificação manual

O import `@` foi conferido contra as regras documentadas (arquivo `.md`, caminho relativo com `./`, linha
fora de code fence e de crase, dentro da raiz do projeto), mas **não foi verificado em execução**:

1. O `agy` (Antigravity) **não está instalado nesta máquina** — nada do lado Antigravity é verificável aqui.
2. O Gemini CLI 0.42.0 está instalado, mas verificá-lo exige confiar a pasta do projeto e abrir sessão
   interativa (`/memory show`) — não executei para não gastar chamada de API sem pedido.

Para conferir: abrir o repo no Gemini CLI (aceitando a confiança da pasta, que ele pede), rodar `/memory show`
e confirmar que o conteúdo do `CLAUDE.md` e do `CONTEXT.md` aparece concatenado sob o `GEMINI.md`. No
Antigravity, `agy list --skills` deve listar `tech_pulse_layout` e `tech_pulse_admin`.

## Observações para decisão futura (não implementadas)

- **O Gemini CLI descobre skills em caminho diferente.** `gemini skills list` mostrou skills globais em
  `~/.gemini/skills/` (**plural**), enquanto `.gemini/skill/` (**singular**) é a convenção do Antigravity,
  documentada no repo irmão. As duas skills criadas servem o **Antigravity**. Se quiser que o Gemini CLI
  também as veja, seria uma terceira cópia em `.gemini/skills/` — não decidido e fora do escopo.
- **O corpo das skills portadas está em inglês**, verbatim (decisão do grilling): traduzir transformaria o
  `diff` de comparação byte a byte em comparação de dois textos escritos independentemente. Reverter é
  barato, desde que nos dois lados.
- **Uma frase fica fora do trecho comparado**: o parágrafo de abertura de cada agente ("You are the
  TechPulse ... specialist..."). O marcador `## Scope` é robusto justamente por ser estável; trocá-lo pelo
  parágrafo criaria um falso positivo silencioso se alguém reescrevesse a frase.
